# FM3.2a: private, evidence-linked tentative interest review

**Release candidate:** `v0.7.5-fm32a-interests1` from last operator-confirmed `v0.7.5-fm31-watch1`.

## Scope

The existing authenticated **Moltbook → Friend Scout** page can now stage a **tentative interest** from one of Bob's *already saved*, source-verified Scout selections of an active saved friend. An item is copied from Bob's prior bounded **WHY** explanation, not generated by a new model call. The source run, chosen post, saved friend handle, and bounded statement remain attached. This is **Bob's previously recorded impression**, not a factual claim about another agent, a mutual relationship, or a new observation.

An owner must click **Stage tentative interest for review** on the selected discussion. No source is added automatically. The separate **Tentative interests** inbox then permits explicit **Approve, Reject, Archive, Reopen**, with optimistic digest checks and immutable local revision history. Approval means *recording owner review only*; it does **not** change FM1 notes, SOUL.md, PM2 memory, Scout selection, publisher configuration, or any external Moltbook action.

## Private data and provenance

Adds two small tables to the existing backed-up private queue database:

- `bob_friend_interest_proposals`: integrity-sealed proposal, run/post/source, status and version, capped at 60.
- `bob_friend_interest_history`: local immutable revision snapshots and operator decisions.

Only verified active FM1 friend records are eligible to stage. Each staging request independently reopens the saved Scout record and checks its exact feed SHA-256, chosen post UUID, author handle, and preexisting WHY. Approval and reopening **repeat** source verification and require the unchanged idea. Unavailable or changed sources cannot be approved; archiving remains possible to clean up. Invalid/double-click/stale forms fail closed; a digest mismatch refuses the operation. The original HTTP Basic authentication (LAN), Host, Origin, CSRF and strict six-field POST handling are reused unchanged. Private friend notes and interests are never passed to a model or Moltbook.

This release adds **no** new managed Python modules, external requests, timers, OpenClaw tools, profile reads, permissions or publication modes. The one-file update changes only `bob_friend_scout.py`. All prior friend-scanning constraints and both auto-publication guards stay intact. The updater takes its normal database backup and supports code rollback. Do not interpret a code-only rollback as undoing later local review records.

## Offline and live acceptance

New synthetic tests exercise independent saved-source validation, staging, stale forms, reversible owner decisions, source tampering, immutable histories, and absence of publication/config changes. The full existing offline suite still needs to pass before merging.

After promotion to `main`:

1. Run **`bobctl update`** once. Confirm `v0.7.5-fm31-watch1` → `v0.7.5-fm32a-interests1`, exactly one changed file, and type **UPDATE**.
2. Open **Moltbook → Friend Scout** via authenticated LAN Activity Manager. Under a source-verified selection by an active saved friend, click **Stage tentative interest for review** (if there is no such prior selection, the stage action is intentionally unavailable).
3. In **Tentative interests**, approve or reject, then use **Reopen**. Verify the local status and history; it does not post, follow, message, change FM1 notes, alter Bob's memory, or change the watch switch.
4. Check Overview / Scout checkpoint or Logs for a successful ordinary scheduled Scout run after the earlier import repair. No need to rerun recovery if already healthy.
