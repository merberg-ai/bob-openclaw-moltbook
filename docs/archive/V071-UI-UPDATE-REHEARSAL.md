# v0.7.1: Responsive UI polish and isolated update-package rehearsal

**Status:** integrated and packaged for offline review; **NOT installed** on the OMEN or approved for deployment.

## What changed in this phase

`webui/navigation_shell.py` now fixes the mobile disclosure-state selector (`details[open]`), adds a keyboard-accessible skip-to-content link and focusable main landmark, gives navigation and buttons at least 44-pixel touch targets, makes input/textarea/select controls fit narrow screens, constrains long report text, and adjusts padding/grid layout at 1050, 760 and 380 pixels. The complete, already escaped HTML generated by the original Scout, Activity and Original Posts renderers remains intact. No JavaScript, API requests or route changes were added.

`scripts/rehearse_v071_ui_update.py` now uses the existing two-file review ZIP from `build_v071_manager_candidate.py` as the candidate format, checks **exact member names and manifest SHA-256 fingerprints** against the known pinned baseline source, compiles both candidate Python files, and stages temporary `baseline` and `candidate` directories. An atomic local symlink selects the candidate. A deliberately simulated failed health check restores the baseline pointer, while **synthetic SQLite writes made after the switch remain untouched**. All files are automatically deleted. Tests reject ZIP extras, tampered manager/navigation bytes, altered deployable status, an unexpected existing path and tampered stage members.

## CI acceptance

GitHub CI passed **128 offline Python tests**, the actual isolated loopback HTTP smoke of the generated three-page Activity Manager, the v0.7.1 UI builder, the v0.7.1 code rollback rehearsal, the original v0.7.0 source rollback, and existing inert service graph/parser/process-lifecycle checks. The Windows PowerShell script syntax job also passed.

## Local developer preview, not an installation

To review candidate integrity only, from the isolated v0.7.1 development checkout:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -q
python3 scripts/build_v071_manager_candidate.py
python3 scripts/rehearse_v071_ui_update.py
```

Optional `python3 scripts/build_v071_manager_candidate.py --private-review-zip` creates a **non-deployable** two-file archive in the private owner-only baseline folder; it does not install or restart the Activity Manager.

## Required before a real UI update

1. Visually review the actual generated page at narrow/mobile and desktop widths in an isolated browser, including the mobile menu, form layouts and scroll behavior. Current CSS checks and GET smoke are not pixel/visual acceptance.
2. Produce a separately reviewed operator release step that checks the live manager's pinned original SHA, confirmed private backup and compatible service entrypoint, and installs **both** manager code and navigation module in a versioned location. The old code must remain directly restorable; no database downgrade should be attempted after new writes.
3. Check the live Activity Manager's LAN authentication, CSRF/origin rejection, approval and publishing UI affordances using a safely isolated acceptance environment, without sending a Moltbook request. Do not use the test archive as an installer.
4. Obtain separate explicit operator approval for the production service update/restart; ensure health and rollback before considering the v0.7.1 milestone complete.

**No service units, startup tasks, credentials, production sources, publishing queue or real SQLite database changed in this phase.**
